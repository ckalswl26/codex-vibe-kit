# 프론트엔드 UI

## 1. 먼저 정할 것 (사용자에게 2~3줄로 제안)
- 핵심 화면 목록과 각 화면의 주요 행동 1개
- 분위기 한 줄 (예: "업무용, 차분, 정보 밀도 높음")
- 기술: 화면 1~2개면 정적 HTML+JS, 상태가 많으면 Vite+React

## 2. 디자인 토큰 (CSS 변수로 한 곳에)
```css
:root {
  --bg: #f7f7f5; --surface: #ffffff; --text: #1d1d1f; --muted: #6b6b70;
  --accent: #2f5bea; --danger: #d64545; --border: #e4e4e7;
  --radius: 10px; --s1: 4px; --s2: 8px; --s3: 16px; --s4: 24px; --s5: 40px;
  --font: "Pretendard", system-ui, sans-serif;
}
```
- 강조색은 하나. 회색 단계로 위계를 만든다.
- 글자 크기는 3~4단계만 (예: 13 / 15 / 20 / 28px).
- 간격은 4의 배수만 쓴다.
- 한글 폰트: Pretendard CDN 또는 system-ui.

## 3. 반드시 있어야 할 상태
- 로딩, 빈 데이터, 에러(다시 시도 버튼), 성공 피드백
- 긴 텍스트, 숫자 0, 목록 1건/많은 건에서도 깨지지 않는지

## 4. 기본 접근성
- 버튼은 `<button>`, 입력에는 `<label>`
- 색 대비 충분, 포커스 표시 유지, 클릭 영역 최소 40px

## 5. AI가 만든 티 줄이기
- 의미 없는 그라데이션·이모지·과한 그림자 금지
- 실제 데이터 같은 문구 사용 ("Lorem ipsum", "Item 1" 금지)
- 카드만 반복하지 말고 정보 성격에 맞게 표/목록/요약 수치를 섞는다

## 6. 함께 설치된 디자인 skill이 있을 때 (vendor.sh --design)
- 색·폰트·스타일 정하기: `ui-ux-pro-max`의 search.py를 한 번 실행해 후보를 받고, 사용자가 고른 것만 토큰에 반영한다.
- 화면 비평·다듬기: `impeccable`의 critique / polish 흐름을 쓴다. 전체를 갈아엎지 말고 지적된 부분만 고친다.
- 여러 디자인 skill을 한 작업에 동시에 불러오지 않는다 (토큰 낭비). 한 번에 하나.

## 7. 확인
- 모바일(390px)과 데스크톱(1280px) 폭에서 확인한다 (`verify-and-test` skill 참고).
