# 디버깅 루프

1. 재현: 문제를 일으키는 가장 짧은 명령/조작을 찾고 실제 에러 메시지 전문(핵심 줄)을 확보한다.
2. 위치: 스택트레이스의 첫 번째 "우리 코드" 줄부터 읽는다. 관련 파일의 해당 부분만 연다.
3. 가설: 원인 후보를 최대 3개, 가능성 순으로 적는다. 각 가설을 확인할 방법(로그 1줄, print, curl)도 적는다.
4. 확인: 가장 싼 확인부터 실행한다. 추측으로 코드를 고치지 않는다.
5. 최소 수정: 원인과 직접 관련된 줄만 고친다. 무관한 리팩터링 금지.
6. 재검증: 1번의 재현 절차를 다시 실행해 해결을 확인하고, 주변 기능 1개도 확인한다.

## 멈춤 규칙
- 같은 가설로 2번 실패 → 수정 중단, 지금까지 확인한 사실/배제된 가설을 사용자에게 보고하고 방향을 묻는다.
- "처음부터 다시 만들기"는 사용자 승인 없이 하지 않는다.
- 의존성 버전 문제로 보이면 버전 확인 명령 결과를 먼저 보여준다.

## 보고 형식
```
증상: ...
원인: ... (근거: ...)
수정: 파일:줄 — 무엇을
확인: 재현 절차 재실행 결과
```
- 원인을 DECISIONS.md나 EXPLAIN.md의 "한계/배운 점"에 한 줄 남길지 사용자에게 묻는다.
