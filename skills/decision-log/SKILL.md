# 결정 기록과 설명 준비

## DECISIONS.md (결정할 때마다 한 줄)
```
| 시각 | 결정 | 이유 (요구사항 근거) | 버린 대안 |
|---|---|---|---|
| 10:35 | SQLite 대신 JSON 파일 | 데이터 50건, 읽기 위주 (M2) | SQLite: 설정 비용 대비 이득 없음 |
```
- 이유는 반드시 요구사항이나 담당자 답변에 연결한다.
- 사용자가 내린 결정과 에이전트가 제안한 것을 구분해 적는다.

## EXPLAIN.md (마무리 15분 전에 작성)
1. 한 문장 요약: 누구의 어떤 문제를 어떻게 푸는가
2. 구조도: 텍스트 다이어그램 (화면 → API → 저장소)
3. 핵심 흐름 1개를 요청부터 응답까지 파일·함수 이름으로 따라가기
4. 주요 결정 3개와 이유 (DECISIONS.md에서)
5. 일부러 안 만든 것과 이유
6. 알려진 한계와 다음에 할 일

## 이해 확인
EXPLAIN.md를 쓴 뒤 사용자에게 코드 기반 질문 5개를 낸다.
- "X 요청이 들어오면 어떤 함수가 어떤 순서로 실행되나?"
- "Y를 왜 이렇게 저장했나? 다른 방식이면 무엇이 달라지나?"
- "Z 입력이 비어 있으면 어떻게 되나?"
사용자가 답하면 틀린 부분만 짧게 바로잡는다. 정답을 먼저 알려주지 않는다.
